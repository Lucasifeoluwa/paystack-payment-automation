# Paystack Payment Automation (n8n + Airtable)

Every Paystack payment is verified, logged once, receipted and announced to the team, and failed charges are swept up daily into a follow-up queue. No manual reconciliation.

Built with **n8n**, **Airtable**, **Paystack**, **Slack** and a small amount of tested JavaScript.

---

## The problem

A business taking payments through Paystack usually ends up with someone copying sales into a spreadsheet, emailing receipts by hand and checking the dashboard for failed charges when they remember to. Sales get missed, receipts go out late or twice, and failed payments from real customers are never followed up.

## What this does

**Workflow 1: Payment Webhook** (`workflows/paystack-payment-webhook.json`)

```
Paystack ──POST──▶ Webhook (raw body, 200 immediately)
                      │
                      ▼
            Verify HMAC-SHA512 signature ──invalid──▶ Slack: rejected webhook
                      │ valid
                      ▼
               charge.success? ──no──▶ ignore
                      │ yes
                      ▼
       Airtable: reference already logged? ──yes──▶ skip (duplicate)
                      │ no
                      ▼
            Log sale in Airtable ──fails 3x──▶ Slack: could not log sale
                      │
                      ▼
               Email receipt ──fails──▶ Slack: send receipt manually
                      │
                      ▼
        Tick "Receipt Sent" ──▶ Slack: new sale
```

**Workflow 2: Daily Failed-Charge Sweep** (`workflows/paystack-failed-charge-sweep.json`)

Paystack's webhooks announce successful charges, but a customer's failed card attempt does not arrive as a webhook event, so failed payments are invisible unless someone checks the dashboard. Every morning at 8am this workflow calls the Paystack API for the last 24 hours of failed transactions, upserts each into Airtable with `Follow-up = Needed`, and posts a summary to Slack.

## Design decisions

**Signature verification on the raw body.** Paystack signs the exact request bytes with HMAC-SHA512 using your secret key. The Webhook node has *Raw Body* enabled and the Code node hashes those bytes. Hashing re-serialised JSON, or using SHA-256, fails every time; both mistakes have unit tests in `test/`. Comparison uses `crypto.timingSafeEqual`.

**Fail closed.** A missing signature, missing raw body, invalid JSON or missing reference is rejected and reported, never processed.

**Idempotent by reference.** Paystack retries webhooks and can deliver the same event more than once. The workflow checks Airtable for the transaction reference before doing anything with side effects, so a retry never creates a second row or a second receipt. The daily sweep uses an Airtable **upsert** keyed on `Reference`, so running it twice changes nothing.

**Every failure path ends with a human told what to do.** The Airtable write and receipt email retry 3 times, 2 seconds apart. If they still fail, Slack gets a specific instruction ("log it manually", "send the receipt manually") with the reference attached, rather than the execution silently erroring.

**Acknowledge first.** The webhook returns 200 as soon as the request arrives, so slow downstream steps never cause Paystack to retry.

**Code lives outside the workflow.** The Code-node JavaScript is in `code/`, unit tested, and injected into the workflow JSON by `scripts/build-workflows.js`. The exported workflow and the tested code cannot drift apart.

## Run it locally

**You need:** Docker, Node 18+, a Paystack account in **test mode**, a free Airtable account, a Slack incoming webhook, and SMTP details for sending email.

1. **Configure.** `cp .env.example .env` and fill it in. Use your `sk_test_` key.
2. **Create the Airtable table** following `airtable/schema.md`.
3. **Start n8n.** `docker compose up -d`, then open http://localhost:5678.
4. **Add credentials in n8n:** an *Airtable Personal Access Token* and an *SMTP* account.
5. **Import both workflows** from `workflows/`, open each Airtable and Send Email node, and select your credentials.
6. **Activate** the Payment Webhook workflow.
7. **Test it:**
   ```bash
   npm test                 # unit tests for the signature logic
   npm run send             # valid payment  → Airtable row, receipt, Slack
   npm run send:duplicate   # same event twice → second one skipped
   npm run send:bad         # tampered signature → rejected, Slack alert
   ```
8. **Point Paystack at it.** To receive real test-mode webhooks, expose port 5678 with a tunnel (for example `cloudflared tunnel --url http://localhost:5678`) and paste `https://<tunnel>/webhook/paystack-webhook` into Paystack: *Settings → API Keys & Webhooks → Test Webhook URL*.

| Signature logic unit tests (`npm test`): SHA-256 mistake, re-serialised JSON, wrong key, tampered body, missing header | 10/10 pass |

The Airtable, SMTP and Slack steps need your own accounts; follow *Run it locally* to exercise them end to end.

## Known limitations

- **Near-simultaneous duplicates.** Airtable has no unique constraint. If Paystack delivered the same event twice within the same second, both could pass the duplicate check before either row is written. In practice Paystack's retries are minutes apart. A production version under heavy load would put the idempotency check in a store with a real unique key (Postgres, Redis `SET NX`).
- **Sweep pagination.** The sweep fetches up to 100 failed transactions per day. Enough for a small business; a larger one would paginate using `meta.pageCount`.
- **Amounts assume a currency with 100 subunits** (NGN kobo, GHS pesewas, ZAR cents, KES cents, USD cents) and divide by 100.
